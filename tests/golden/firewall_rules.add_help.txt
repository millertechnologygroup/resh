Handle: firewall
Verb: rules.add
Definition: Adds a rule to the selected backend, for IPv4 and IPv6 alike when
  family=any is given without an address, skipping any rule that already exists
  unless idempotent=false is given.

Usage:
  resh firewall://.rules.add
    [backend=auto|iptables|nftables|ufw|firewalld]
    [family=ipv4|ipv6|any]
    [direction=input|output|forward|prerouting|postrouting]
    [action=accept|drop|reject|log|masquerade|dnat|snat|redirect]
    [table=<table>] [chain=<chain>] [proto=<proto>] [sport=<port>]
    [dport=<port>] [saddr=<cidr>] [daddr=<cidr>] [in_iface=<iface>]
    [out_iface=<iface>] [zone=<zone>] [log_prefix=<text>]
    [rate_limit=<rate>] [comment=<text>] [position=append|insert]
    [dry_run=true|false] [idempotent=true|false] [timeout_ms=<ms>]
    [format_output=json|text]

Example:
  resh --json-pretty firewall://.rules.add proto=tcp dport=22 dry_run=true

  Shown for a host where iptables is detected, with --json-pretty. family
  defaults to ipv4. With family=any and no address, iptables gets one rule per
  family: rules lists both and rule is null. A saddr or daddr sets the family;
  an explicit family that differs is rejected
  (firewall.rules_add_family_mismatch). On nftables the rule goes into the
  live chain hooked on direction (an inet table first), or the given
  table/chain (firewall.chain_not_found if there is none). sport and dport need
  proto=tcp or proto=udp; log_prefix needs action=log; dnat and snat are
  refused; zone is required for firewalld and refused elsewhere
  (firewall.unsupported_option).
